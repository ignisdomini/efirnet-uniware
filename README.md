# EFIRNET UNIWARE V.1

Мультизагрузчик для плат проекта **ЭФИРНЕТ**. Одна плата — три независимые
прошивки (ЭФИРНЕТ, Meshtastic, MeshCore), выбор кнопкой PRG в меню на экране
при каждом включении. Заливается из браузера на `/flash.php`, как и обычная
прошивка ЭФИРНЕТа.

```
+------------------------------+     +------------------------------+
| EFIRNET UNIWARE V.1          |     |  ####################        |
| ---------------------------- |     |                              |
|[. ЭФИРНЕТ                  ] |     |        EFIRNET               |
|   MESHTASTIC                 |     |      UNIWARE  V.1            |
|   MESHCORE                   |     |     ------------             |
|                              |     |       EFIRNET.RU             |
| #########                    |     |  #######                     |
+------------------------------+     +------------------------------+
        меню выбора                          заставка
```

---

## Как поставить на плату

Готовые образы — в разделе [Releases](../../releases). Скачайте архив,
распакуйте, поставьте `esptool` и залейте:

```bash
pip install esptool
```

```bash
python tools/flash_release.py heltec_v3 COM6 --erase
```

Вместо `COM6` — свой порт: на Linux и macOS это `/dev/ttyUSB0` или
`/dev/cu.usbserial-*`. Список плат покажет запуск без аргументов.

`--erase` при первой установке обязателен: комплект переразмечает флеш
целиком, и остатки прежней разметки лягут посреди чужих слотов.

Смещения скрипт берёт из `manifest.json` рядом с образами, руками их
задавать не нужно. Кто предпочитает esptool напрямую — команда целиком
лежит в `ПРОШИТЬ.txt` внутри каждого комплекта.

После заливки включите плату: появится заставка, затем меню из трёх сетей.

## Поддерживаемые платы

UNIWARE собирается для тех плат, у которых хватает флеша на три прошивки **и**
для которых существуют апстримные варианты Meshtastic и MeshCore.

| Плата | Чип | Флеш | Meshtastic | MeshCore | Экран |
|---|---|---|---|---|---|
| `heltec_v3` | ESP32-S3 | 8 МБ | `heltec-v3` | `Heltec_v3_companion_radio_ble` | есть |
| `heltec_stick_lite_v3` | ESP32-S3 | 8 МБ | `heltec-wsl-v3` | `Heltec_WSL3_companion_radio_ble` | **нет** |
| `lilygo_t3s3` | ESP32-S3 | 8 МБ | `tlora-t3s3-v1` | `LilyGo_T3S3_sx1262_companion_radio_ble` | есть |
| `heltec_v2` | ESP32 | 8 МБ | `heltec-v2_1` | `Heltec_v2_companion_radio_ble` | есть |
| `heltec_v4` | ESP32-S3 | 16 МБ | `heltec-v4` | `heltec_v4_companion_radio_ble` | есть |
| `heltec_v4_r8` | ESP32-S3 | 16 МБ | `heltec-v4-r8-oled` | `heltec_v4_r8_companion_radio_ble` | есть |

Остальные платы ЭФИРНЕТа в UNIWARE не входят, и вот почему:

* `ttgo_lora32_v21`, `tbeam_v11` — 4 МБ флеша. Meshtastic одна занимает больше
  2 МБ; вместе с ЭФИРНЕТом и менеджером три прошивки туда не помещаются.
* `ttgo_lora32_v1`, `generic_sx1276`, `generic_sx1262`, `generic_sx1268_433` —
  для них нет ни образов Meshtastic, ни MeshCore. Соседей просто нет.

На всех этих платах остаётся обычная однопрошивочная сборка ЭФИРНЕТа.

**Плата без экрана.** У `heltec_stick_lite_v3` дисплея нет, поэтому меню там
озвучивается светодиодом: номер выбранной прошивки — столько же вспышек
(1 = ЭФИРНЕТ, 2 = Meshtastic, 3 = MeshCore). Полный список одновременно идёт
в UART на 115200 — с компьютера видно, что выбрано.

## Часть 1. Раскладка памяти

Метки разделов одинаковы во всех раскладках — меняются только размеры. Благодаря
этому менеджер и вставка не знают, на какой плате работают: они ищут разделы по
имени.

### 8 МБ — `partitions_triboot_8mb.csv`

| Метка | Тип | Подтип | Смещение | Размер | Кому |
|---|---|---|---:|---:|---|
| `nvs` | data | nvs | `0x009000` | 20 КБ | общий: калибровка ВЧ + выбор в меню + Meshtastic |
| `otadata` | data | ota | `0x00e000` | 8 КБ | указатель «что грузить» |
| `factory` | app | factory | `0x010000` | 448 КБ | **EFIRNET UNIWARE** |
| `app_efr` | app | ota_0 | `0x080000` | 896 КБ | ЭФИРНЕТ |
| `app_mt` | app | ota_1 | `0x160000` | 2688 КБ | Meshtastic |
| `app_mc` | app | ota_2 | `0x400000` | 1664 КБ | MeshCore |
| `nvs_efr` | data | nvs | `0x5a0000` | 20 КБ | настройки ЭФИРНЕТа |
| `nvs_mc` | data | nvs | `0x5a5000` | 20 КБ | настройки MeshCore |
| `lfs_efr` | data | spiffs | `0x5aa000` | 280 КБ | ФС ЭФИРНЕТа (резерв) |
| `mc_fs` | data | spiffs | `0x5f0000` | 576 КБ | ФС MeshCore |
| `spiffs` | data | spiffs | `0x680000` | 1536 КБ | ФС Meshtastic |

### 16 МБ — `partitions_triboot_16mb.csv`

Те же метки, шире слоты: `app_efr` 1536 КБ (`0x080000`), `app_mt` 4096 КБ
(`0x200000`), `app_mc` 3072 КБ (`0x600000`), `mc_fs` 2048 КБ, `spiffs` 4096 КБ.

Обе таблицы заполняют флеш ровно до последнего байта, все `app`-разделы
выровнены по 64 КБ, как требует загрузчик.

Два ограничения, которые нужно принять осознанно:

* **OTA внутри целевых прошивок пропадает.** Каждой достаётся один слот, второго
  под скачивание обновления нет. Обновление — по USB или через сайт.
* **`otadata` обязан остаться на `0xe000`.** Именно туда PlatformIO пишет
  `boot_app0.bin` при обычной заливке. Сдвинете — заливка любой прошивки будет
  портить соседний раздел.

## Часть 2. Загрузчик EFIRNET UNIWARE

Живёт в `factory`. Пины он **не знает сам** — берёт их из `board_pins.h` проекта
ЭФИРНЕТ, того же файла, что использует сама прошивка. Плата задаётся флагом
`-D BOARD_*`, поэтому новая плата добавляется одним окружением, без правок кода.

```bash
cd bootmanager
pio run -e heltec_v3
```

```bash
cd bootmanager && pio run -e heltec_v3 -e heltec_v4 -e heltec_v4_r8 -e lilygo_t3s3 -e heltec_stick_lite_v3 -e heltec_v2
```

### Что делает

1. Поднимает Vext (там, где он есть) — без этого OLED не получит питания.
2. 1.6 с показывает заставку `EFIRNET / UNIWARE V.1 / EFIRNET.RU`.
3. Читает таблицу разделов и проверяет каждый слот `app_*` (разбирает
   `esp_app_desc_t`). Пустые слоты в меню не показываются вовсе.
4. Показывает меню — только названия сетей, точкой помечена прошивка по
   умолчанию, внизу полоса обратного отсчёта — и ждёт 6 секунд.
5. `esp_ota_set_boot_partition()` + `esp_restart()`.

### Управление PRG

| Действие | Что происходит |
|---|---|
| нажатие во время заставки | заставка пропускается, автостарт отменяется |
| короткое нажатие | следующий пункт меню (пустые слоты пропускаются) |
| удержание > 700 мс | загрузить выбранное |
| ничего не делать 6 с | грузится то, что выбирали в прошлый раз (помнится в NVS) |

> **Кнопка сидит на strapping-пине GPIO 0.** Держать её в момент сброса нельзя:
> чип уйдёт в UART-загрузчик, а не в меню. Кнопку нажимают уже после заставки.

## Часть 3. Сборка целевых прошивок

Все три прошивки собираются из исходников. Это не прихоть: режим «меню при
каждом включении» требует, чтобы прошивка сама возвращала `otadata` загрузчику,
а готовому бинарнику этого не привить.

| Прошивка | Каталог | Версия |
|---|---|---|
| ЭФИРНЕТ | `../efirnet/firmware` | v1.2 |
| Meshtastic | `../meshtastic-src` | тег `v2.7.26.54e0d8d` |
| MeshCore | `../meshcore-src` | тег `companion-v1.17.0` |

### Правило изоляции

NVS терпит соседей: у каждого приложения свои namespace'ы. **Файловые системы —
не терпят.** Если две прошивки монтируют один раздел `spiffs`, одна из них рано
или поздно его отформатирует.

> **Ровно одна прошивка держит канонические имена `nvs` и `spiffs`.
> Остальным правится ровно одна строка монтирования.**

Канон отдан Meshtastic: она самая сложная, и её `nvs` в штатной таблице стоит на
том же `0x9000` размером `0x5000`, что и у нас. Её код монтирования не тронут вовсе.

### Общая для всех часть

В каждый проект кладётся `dualboot_return.cpp`, и добавляется
окружение-наследник с четырьмя настройками:

```ini
board_build.partitions         = <наша таблица, 8 или 16 МБ>
board_upload.offset_address    = <смещение своего слота>
board_build.app_partition_name = <метка своего слота>
build_flags                    = ... -D DUALBOOT_ALWAYS_MENU=1
```

> **`app_partition_name` обязателен.** Без него PlatformIO берёт для проверки
> размера первый `app`-раздел таблицы — `factory` на 448 КБ — и валит сборку
> с `The program size … is greater than maximum allowed (458752 bytes)`, хотя
> образ прекрасно помещается в свой слот. Напоролся и на MeshCore, и на ЭФИРНЕТе.

### ЭФИРНЕТ

Шесть окружений `*_uniware` дописаны в конец `firmware/platformio.ini`; штатные
окружения не тронуты, у них прежняя раскладка с двумя OTA-слотами. Единственная
правка исходника — `src/storage.cpp`, под `#ifdef`:

```cpp
#ifdef EFIRNET_NVS_PARTITION
    prefs.begin("efirnet", false, EFIRNET_NVS_PARTITION);
#else
    prefs.begin("efirnet", false);
#endif
```

`Preferences::begin()` с третьим аргументом сам вызывает `nvs_flash_init_partition()`.

```bash
cd ../efirnet/firmware && pio run -e heltec_v3_uniware -e heltec_stick_lite_v3_uniware -e lilygo_t3s3_uniware -e heltec_v4_uniware -e heltec_v4_r8_uniware -e heltec_v2_uniware
```

### Meshtastic

> **Имя окружения для V4 R8 намеренно короткое — `hv4r8-uniware`.** С полным
> `heltec-v4-r8-oled-uniware` сборка стабильно падает пачкой
> `xtensa-esp32s3-elf-g++: error: CreateProcess: No such file or directory`:
> имя окружения входит во все пути `.pio/build`, и командная строка компилятора
> упирается в предел Windows.

> **Конфиг правьте до сборки, а не между.** Любая правка `platformio.ini`
> меняет `project.checksum`, и следующий `pio run` сносит **все** каталоги
> `.pio/build` проекта, а не только затронутое окружение. Переименование одного
> окружения стоило здесь пяти уже готовых сборок.


Правок исходников нет вовсе: `dualboot_return.cpp` просто лежит в `src/`, где
его подхватывает штатный `build_src_filter`. Таблицы разделов скопированы в
корень репозитория, окружения — в `variants/esp32s3/uniware.ini` (этот путь уже
перечислен в `extra_configs` самой Meshtastic).

```bash
cd ../meshtastic-src && pio run -e heltec-v3-uniware -e heltec-wsl-v3-uniware -e tlora-t3s3-v1-uniware -e heltec-v2_1-uniware -e heltec-v4-uniware -e hv4r8-uniware
```

### MeshCore

Одна правка исходника — `examples/companion_radio/main.cpp`, единственное место,
где ESP32-сборка монтирует файловую систему:

```cpp
SPIFFS.begin(true, "/spiffs", 10, "mc_fs");   // было: SPIFFS.begin(true);
```

Preferences MeshCore не использует вовсе — все настройки лежат в файловой
системе, так что раздел `nvs_mc` ей формально не нужен и оставлен в резерве.
Окружения — в `platformio.local.ini` (тоже уже перечислен в `extra_configs`).

```bash
cd ../meshcore-src && pio run -e Heltec_v3_uniware -e Heltec_WSL3_uniware -e LilyGo_T3S3_uniware -e Heltec_v2_uniware -e heltec_v4_uniware -e heltec_v4_r8_uniware
```

Берётся вариант `companion_radio_ble` — тот, что работает с телефоном по
Bluetooth. Если нужен USB-вариант, поменяйте базовое окружение на
`*_companion_radio_usb`, всё остальное останется как есть.

### Вставка `dualboot_return.cpp`

После `esp_ota_set_boot_partition()` запись в `otadata` постоянная. Вставка даёт
два поведения, переключаемых флагом:

* `DUALBOOT_ALWAYS_MENU=0` — **прямая загрузка.** Выбранная прошивка стартует
  мгновенно при каждом включении, меню не показывается. Вернуться — удержать PRG
  2 секунды в первые 12 секунд после старта.
* `DUALBOOT_ALWAYS_MENU=1` — **меню всегда.** Прошивка прямо в конструкторе, до
  `setup()`, стирает `otadata`. Каждое включение открывает меню, в нём подсвечена
  и помечена точкой последняя выбранная прошивка, и она же уходит в автостарт по
  таймауту. Это то, что собирается для сайта.

Сторожевая задача PRG работает в обоих режимах и загрузку не задерживает.

> **Класть файл в `lib/` нельзя.** Проверено: PlatformIO упаковывает библиотеку
> в архив `.a`, ссылок на этот файл ни у кого нет, и компоновщик выбрасывает
> объектный файл вместе с конструктором — возврат молча не работает. Из `src/`
> или из папки, добавленной через `build_src_filter`, символы остаются в ELF.

Стирание `otadata` выбрано намеренно вместо `esp_ota_set_boot_partition(factory)`:
в IDF 4.4 поведение этой функции на разделе типа `factory` неочевидно, а стирание
сектора делает ровно то же, что проверенная команда `erase_region 0xe000 0x2000`,
и ни от чего не зависит.

## Часть 4. Онлайн-прошивка

```bash
python tools/build_web_bundles.py
```

```bash
python tools/build_web_bundles.py --check
```

Скрипт раскладывает по `efirnet/web/fw/<плата>_uniware/` семь файлов и
`manifest.json` рядом с ними. Страница `/flash.php` читает каталог `fw/` сама
(`web/api/firmware.php` обходит `fw/*/manifest.json`), поэтому в сайте ничего
править не нужно — сборки появляются в выпадающем списке сразу.

Что пишется в плату:

| Файл | Смещение (8 МБ) | Смещение (16 МБ) |
|---|---|---|
| `bootloader.bin` | `0x0` (ESP32-S3) / `0x1000` (ESP32) | `0x0` |
| `partitions.bin` | `0x8000` | `0x8000` |
| `otadata_blank.bin` | `0xe000` | `0xe000` |
| `uniware.bin` | `0x10000` | `0x10000` |
| `efirnet.bin` | `0x80000` | `0x80000` |
| `meshtastic.bin` | `0x160000` | `0x200000` |
| `meshcore.bin` | `0x400000` | `0x600000` |

`otadata_blank.bin` — восемь килобайт `0xFF`. Отдельной команды «стереть» у
esptool-js нет, но запись `0xFF` равносильна стиранию: сектор всё равно чистится
перед записью. Благодаря этому плата после заливки поднимается именно в меню,
а не в случайный слот.

**Образы файловых систем не заливаются.** У Meshtastic образ `littlefs` пустой
(1.5 МБ, сжимается до двух килобайт), MeshCore свой раздел форматирует сама при
первом запуске. Гонять эти мегабайты через браузер незачем.

## Заливка с компьютера

```bash
bash tools/flash_triboot.sh COM6
```

Скрипт заливает всё, что нашёл на диске, и в конце стирает `otadata`, чтобы
плата поднялась в меню. Вручную, по шагам, — `--flash_mode/freq/size keep`
намеренно: у каждого образа в заголовке уже стоят значения, с которыми его
собирали, а переписывание их своими даёт плату в вечном ребуте.

```bash
python -m esptool --chip esp32s3 -p COM6 erase_flash
```

```bash
python -m esptool --chip esp32s3 -p COM6 -b 921600 write_flash -z --flash_mode keep --flash_freq keep --flash_size keep 0x0 bootmanager/.pio/build/heltec_v3/bootloader.bin 0x8000 bootmanager/.pio/build/heltec_v3/partitions.bin 0x10000 bootmanager/.pio/build/heltec_v3/firmware.bin
```

```bash
python -m esptool --chip esp32s3 -p COM6 erase_region 0xe000 0x2000
```

После заливки через `pio run -t upload` тоже нужен `erase_region 0xe000 0x2000`:
PlatformIO попутно пишет `boot_app0.bin` в `otadata` и переводит плату на `ota_0`.

## Что проверено

### Собрано и сверено по размерам — все шесть плат

Двадцать четыре образа: менеджер, ЭФИРНЕТ, Meshtastic и MeshCore на каждую плату.
Худший запас — 84 %, и то лишь у трёх слотов.

### Прогнано на живом железе — только Heltec V3

Плата `f0:9e:9e:75:8d:18` (ESP32-S3 rev v0.2, флеш GD 8 МБ), COM6,
5 сентября 2026. Дамп до первой заливки — `BACKUP_f09e9e758d18_before_uniware_8MB.bin`.

**Режим «меню всегда» работает.** Каждый цикл включения даёт одно и то же:

```
rst:0x1  (POWERON)          <- factory: заставка 1.6 с + меню 6 с
=== EFIRNET UNIWARE  V.1 · EFIRNET.RU ===
   1) ЭФИРНЕТ
 > 2) MESHTASTIC    (по умолчанию)
   3) MESHCORE
[UNIWARE] запускаю MESHTASTIC
rst:0xc  (RTC_SW_CPU_RST)   <- esp_restart() из меню
```

После цикла `otadata` снова пуст — прошивка вернула управление загрузчику, и
следующее включение опять откроет меню.

**Вставка сработала во всех трёх прошивках.** Вручную подставлялся `otadata` на
нужный слот, прошивка запускалась, затем `otadata` читался обратно: ЭФИРНЕТ —
пуст, Meshtastic — пуст, MeshCore — пуст. У Meshtastic это было под вопросом:
она собирается с LTO, символа `dualboot_return_install` в ELF не остаётся,
компоновщик сливает все конструкторы в один `_GLOBAL__I_65535_0_...`.

**У MeshCore своя файловая система.** Первая загрузка после чистого флеша:
`E (169) SPIFFS: mount failed, -10025`, затем Arduino-обёртка форматирует раздел
(в первом секторе `mc_fs` появилось 203 не-0xFF байта). Вторая загрузка — без
единой ошибки. Раздел `spiffs` от Meshtastic при этом не тронут.

### Что не проверено

* Пять плат, кроме Heltec V3, на живом железе не запускались — их под рукой нет.
* Нажатия PRG: короткое (следующий пункт), длинное (пуск) и удержание 2 с для
  возврата в меню из работающей прошивки.
* Светодиодное меню на `heltec_stick_lite_v3` — только собрано.
* Онлайн-заливка через браузер: комплекты собраны и разложены, но сама страница
  с ними не прогонялась.

Перед экспериментами на своей плате снимите дамп:

```bash
python -m esptool --chip esp32s3 -p COM6 -b 921600 read_flash 0x0 0x800000 backup_8MB.bin
```
